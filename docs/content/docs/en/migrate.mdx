## Native CSS Major-Release Migration

This major release moves theme styling to published native CSS and Tailwind
outputs and removes Stylus, its renderer integration, and
`hexo-renderer-stylus`. Sites that install the theme through a package manager
use the CSS included in the published package. If a site installed
`hexo-renderer-stylus` only for Redefine, it can remove that dependency.

**Note:** The side-toolbar font increase and decrease controls were removed
because they adjusted only selected `rem`-based sizes, resulting in inconsistent
scaling. Use browser zoom instead (for example, `Ctrl`/`Cmd` + `+` or `-`) to
scale the complete page.

### Update Custom Page Templates

Custom page layouts are now selected only by the `template` front-matter field.
Title matching and legacy `type` values no longer select special layouts. Update
existing custom pages to use the documented value: `categories`, `tags`,
`links`, `masonry`, `bookmarks`, or `essays`. Unknown or missing values render as
ordinary pages.

```yaml
---
title: Friends
template: links
---
```

### Review Custom Geometry

Theme-owned spacing and border radii now use Tailwind's default scales instead
of Redefine-specific spacing and radius variables. Framed route content and
standalone components use `rounded-2xl`; nested article modules use
`rounded-xl`. The default `articles.style.image_border_radius` value changes
from `14px` to `12px`. Existing explicit configuration continues to override
that default.

### Update Custom CSS and JavaScript Selectors

This release removes undocumented DOM class names used only by the theme's
internal styling, without compatibility aliases. Any custom CSS or JavaScript
targeting those internal names must be updated against the currently generated
markup.

- Use semantic selectors for elements such as `header`, `main`, `footer`, and
  `dialog`, along with `role` and `aria-*` state.
- Use focused `data-*` hooks for repeated behavior or state, such as
  `data-state`, `data-search-trigger`, `data-tabs`, and `data-toc-state`.
- When JavaScript needs a unique page region, use current IDs such as `navbar`,
  `page-shell`, `main-content`, `site-footer`, and `side-tools`. Do not use these
  IDs as styling selectors in new theme CSS.

Do not treat generated Tailwind utility classes as replacement interfaces for
the removed internal classes. Documented content scopes such as `markdown-body`
and classes required by third-party integrations such as Waline, Gitalk, and
Twikoo remain available, so custom rules that target only those scopes or
third-party classes do not need to be rewritten solely for this migration.

## Migrating from v1 to v2

If you are using version v1.x.x of the Redefine theme, it is recommended to upgrade to version v2.x.x as soon as possible.

The v1 version is no longer maintained, and the v2 version has undergone code refactoring and is no longer compatible with the configuration files of v1 version.

Therefore, you need to follow the steps below to migrate the v1 version configuration files to v2 version.

If you still need to read the documentation for the v1 version, you can visit the [v1 version documentation](https://redefine-docs-v1.ohevan.com/).

### Migration Steps


<div className="fd-steps [&_h3]:fd-step">

### Update the theme

<Tabs items={["npm", "pnpm"]}>
  <Tab value="npm">
    Execute the following command to update the theme:

    ```bash filename="Terminal"
    npm install hexo-theme-redefine@latest
    ```

  </Tab>
  <Tab value="pnpm">
    Execute the following command to update the theme:

    ```bash filename="Terminal"
    pnpm update hexo-theme-redefine --latest
    ```

  </Tab>
</Tabs>

### Backup v1 configuration file

After updating the theme, rename your original v1 version configuration file `_config.redefine.yml` to `_config.redefine.v1.yml`.

### Create v2 configuration file

In the root directory of your site, **create** a `_config.redefine.yml` file, and then **copy** the configuration file from [here](https://github.com/EvanNotFound/hexo-theme-redefine/blob/main/_config.yml) into it.

### Migrate configuration options

In the v2 version configuration file, the configuration options have been refactored, so please refer to the v1 version configuration file and migrate the configuration options accordingly.

If the migration is difficult, feel free to re-read the [v2 version documentation](/getting-started) and reconfigure the configuration options.

### Delete v1 configuration file (optional)

After **completing the migration and testing the site without any issues**, delete the `_config.redefine.v1.yml` file in the root directory of your site.
