## Getting Ready for Development

<div className="fd-steps [&_h3]:fd-step">

### Work from the repository root

Open the theme repository in your editor and run the commands below from its root directory. The repository uses pnpm `11.20.0` and Node.js 24.x.

### Install dependencies

```bash
pnpm install --frozen-lockfile
```

This installs dependencies for the theme, the local Hexo demo site in `dev/site`, and the docs workspace.

### Enable theme development mode

For a Hexo site using the theme source, set `developer.enable` to `true` in its `_config.redefine.yml` file. The local demo site already enables this option in `dev/site/_config.redefine.yml`.

```yaml
developer:
  enable: true
```

### Start the local demo site

```bash
pnpm dev
```

This serves browser JavaScript source modules directly, resets the demo site's
generated state, links the current theme source into
`dev/site/themes/redefine`, starts Hexo at `http://127.0.0.1:4000`, and watches
Tailwind CSS. It does not require or continuously watch production JavaScript
output.

</div>

## Build and Reset

Run these commands from the repository root:

```bash
pnpm clean
pnpm run build
pnpm run build:css
pnpm run build:js
pnpm run watch:css
```

- `pnpm clean` removes the demo site's generated `db.json` and `public/` directory.
- `pnpm run build` coordinates the Tailwind CSS and browser JavaScript builds.
- `pnpm run build:css` builds `source/css/build/tailwind.css`.
- `pnpm run build:js` bundles the application, writes lazy feature chunks and
  standalone plugin outputs, copies vendor JavaScript, and writes source maps
  under `source/js/build/`.
- `pnpm run watch:css` watches and rebuilds Tailwind CSS without starting Hexo.

Do not edit generated files directly. Theme build output lives in
`source/css/build/` and `source/js/build/`; these paths are generated locally or
in CI and are not committed. Edit the source files instead. Runtime assets under
`source/assets/` remain checked in. When developer mode is disabled, Hexo also
compresses the configuration-dependent Stylus stylesheet; developer mode keeps
that stylesheet readable.

## Preview Release Notes

Version bumps and Git tag creation remain manual. Before pushing a matching
version tag, generate and check the bilingual release-note preview:

```bash
RELEASE_LLM_URL=... RELEASE_LLM_KEY=... pnpm release:notes -- v2.10.0
pnpm release:notes:check
```

The target tag may not exist yet. These commands only write the Git-ignored
`release-notes.md` at the repository root; they do not publish npm or CDN
assets and do not create a GitHub Release. Review the output before pushing the
matching version tag. CI builds the theme before creating the GitHub Release.
If OpenCode is unavailable or its output fails validation, CI uses GitHub
automatic release notes.

## Project Layout

- `source/css/tailwind.source.css`: Tailwind CSS entry file.
- `source/css/`: Stylus and other theme styles.
- `source/assets/`: Checked-in runtime assets.
- `source/js/`: Browser-side JavaScript source.
- `scripts/`: Hexo generation-time Node scripts.
- `layout/`: Hexo templates.
- `dev/site/`: Local demo-site configuration, posts, pages, and fixtures.

## Customizing the Theme

Edit `source/css/tailwind.source.css` for Tailwind utilities and theme CSS. For non-Tailwind styles, update the relevant files under `source/css/` and use the resulting classes in templates under `layout/`.

For more information, see the [official Tailwind CSS documentation](https://tailwindcss.com/docs).
