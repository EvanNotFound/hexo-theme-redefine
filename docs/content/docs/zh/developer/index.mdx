## 开发准备

<div className="fd-steps [&_h3]:fd-step">

### 在仓库根目录开发

请在编辑器中打开主题仓库，并从仓库根目录执行下面的命令。仓库使用 pnpm `11.20.0` 和 Node.js 24.x。

### 安装依赖

```bash
pnpm install --frozen-lockfile
```

该命令会安装主题、本地 Hexo 演示站 `dev/site` 和文档工作区所需的依赖。

### 启用主题开发模式

如果要在 Hexo 站点中使用主题源代码，请在站点的 `_config.redefine.yml` 中将 `developer.enable` 设置为 `true`。本地演示站已经在 `dev/site/_config.redefine.yml` 中启用了此选项。

```yaml
developer:
  enable: true
```

### 启动本地演示站

```bash
pnpm dev
```

该命令会先构建一次浏览器端 JavaScript，清理演示站生成的状态，将当前主题源代码链接到 `dev/site/themes/redefine`，在 `http://127.0.0.1:4000` 启动 Hexo，并实时编译 Tailwind CSS。它不会持续监听浏览器端 JavaScript。

</div>

## 构建与清理

请在仓库根目录执行以下命令：

```bash
pnpm clean
pnpm run build
pnpm run build:css
pnpm run build:js
pnpm run watch:css
```

- `pnpm clean` 删除演示站生成的 `db.json` 和 `public/` 目录。
- `pnpm run build` 构建 CSS 并压缩浏览器端 JavaScript。
- `pnpm run build:css` 生成 `source/css/build/tailwind.css`。
- `pnpm run build:js` 在 `source/js/build/` 下生成压缩后的 JavaScript 和 source map；这些文件属于生成输出。
- `pnpm run watch:css` 只监听并重新构建 Tailwind CSS，不会启动 Hexo。

请勿直接修改构建输出。主题构建输出位于 `source/css/build/` 和 `source/js/build/`，由本地开发或 CI 生成且不会提交到 Git，应当修改对应的源文件。`source/assets/` 下的运行时资源仍然会提交到仓库。

## 预览发布说明

版本号更新和 Git 标签创建仍由维护者手动完成。在推送匹配版本的标签前，可以使用下列命令生成并检查双语发布说明：

```bash
RELEASE_LLM_URL=... RELEASE_LLM_KEY=... pnpm release:notes -- v2.10.0
pnpm release:notes:check
```

目标标签可以暂时不存在。命令只会在仓库根目录生成被 Git 忽略的 `release-notes.md`，不会发布 NPM 或 CDN 资源，也不会创建 GitHub Release。确认内容后再推送匹配的版本标签；CI 会先构建主题，再创建 GitHub Release。如果 OpenCode 不可用或生成内容未通过检查，CI 会改用 GitHub 自动生成的说明。

## 项目结构

- `source/css/tailwind.source.css`：Tailwind CSS 入口文件。
- `source/css/`：Stylus 和其他主题样式。
- `source/assets/`：提交到仓库的运行时资源。
- `source/js/`：浏览器端 JavaScript 源代码。
- `scripts/`：Hexo 生成阶段使用的 Node 脚本。
- `layout/`：Hexo 模板。
- `dev/site/`：本地演示站的配置、文章、页面和测试内容。

## 自定义主题

如果要使用 Tailwind CSS 修改样式，请编辑 `source/css/tailwind.source.css`。如果要编写非 Tailwind 样式，请修改 `source/css/` 下对应的文件，并在 `layout/` 中使用生成的 class。

详细的 Tailwind CSS 文档请参考 [Tailwind CSS 官方文档](https://tailwindcss.com/docs)。
